| 데이터 | 표본 | 결과 | 신뢰도 |

**방향은 두 데이터가 일치하지만, 존3 실거래 표본으로는 실차단을 정당화하기 부족하다.**

## 1. 매매일지에서 얻은 것과 못 얻은 것

### 못 얻은 것 — 타점 패턴은 변별력이 없다

본문 45,547건에서 타점 관련 표현을 추출하고 익절·손절 동반 여부로 대조했다.

| 타점 패턴 | 언급 | 익절 동반 | 손절 동반 | 익절/손절 |
|---|---:|---:|---:|---:|
| 시초/시가진입 | 6,625 | 74.0% | 61.5% | 1.20 |
| 전고점/신고가 | 5,540 | 70.8% | 58.4% | 1.21 |
| 오후/종가베팅 | 4,274 | 71.0% | 59.1% | 1.20 |
| 눌림목진입 | 3,387 | 72.3% | 62.4% | 1.16 |
| 지지확인후진입 | 341 | 73.3% | 62.2% | 1.18 |
| 거래량확인 | 265 | 73.2% | 61.9% | 1.18 |
| 돌파진입 | 1,326 | 74.1% | 68.6% | **1.08** |
| 이평지지 | 257 | 75.9% | 72.0% | **1.05** |

**비가 1.05~1.21로 사실상 차이가 없다.** 원 보고서가 밝힌 한계대로, 키워드 공출현은 행동·순서·결과를 가르지 못한다. 같은 글에 익절과 손절이 함께 적히는 경우가 대부분이다.

따라서 **일지를 타점 규칙의 근거로 쓰지 않는다.**

### 얻은 것 — 방향 교차확인과 경계 신호

- **이평지지(1.05)·돌파(1.08)가 최하위**다. 자체 측정에서 MA20 반등 진입이 엣지 없음(41,377건, 최선 −1.15%)과 방향이 같다.
- 태그 공출현에서 **뇌동 + 돌파 리프트 1.72**, **뇌동 + 손절 1.54**. 돌파 추격이 충동 매매·손절과 함께 나타난다.
- **물타기/불타기 + 추가매수 리프트 4.28**, **물타기 + 손절 1.73**. 자체 ai_swing DCA 청산 6건 100% 손절과 같은 방향.

표본 산출: 존3 라운드트립 **43건** − OHLCV 캐시 결손 **5건**(001210·042510·452190) = **38건**.

| **20일 모멘텀** | +19.97% | +33.24% | **−13.27** |

**이익군이 모든 과확장 지표에서 일관되게 낮다.** 가장 큰 격차는 20일 모멘텀이다.

평균으로는 이익군이 높지만(7.28 vs 3.54), **중앙값은 반대**(1.18 vs 1.97)이고 금액가중 PF로 구간을 나눠도 **역전**한다.

평균과 중앙값이 반대 방향이라는 것은 **소수 이상치가 평균을 끌어올렸다**는 뜻이다. 일지의 '거래량확인'(1.18)도 변별력이 없었다. **거래량 필터는 쓰지 않는다.**

## 4. 구현

`backend/core/strategy/zone_entry_gates.py` 에 **세 번째 게이트** 추가.

```
BARRO_ZONE_MAX_MOM20_PCT=30      # 0 또는 미설정 = OFF (기본)
BARRO_ZONE_MOM_GATE_SHADOW=1     # ★게이트별★ 측정 전용 — 모멘텀만 미차단
```

- 기존 ①정배열 ②재진입 게이트와 같은 방식으로 합성된다
- 데이터 부족(22봉 미만)·종가 이상치는 **fail-open**(차단하지 않음)
- 존3 외 전략에는 영향 없음 / 미설정 시 라이브 거동 불변(§2 S3)

### ★교정 1 — 전역 SHADOW 는 쓰면 안 된다 (라이브 결함이었음)

초판은 `BARRO_ZONE_GATE_SHADOW=1`(전역)로 측정을 시작했다. 그런데 전역 shadow 는
`return (not cfg.shadow), ...` 로 **①정배열 ②재진입 ③모멘텀 전부**를 미차단으로 만든다.

```
하락 일봉 + trend_enabled=True + shadow=True
  정배열 게이트 단독: blocked=True   (이격 −1.28%)
  종합 판정:         blocked=False  ← 이미 차단 중이던 정배열이 해제됨
```

11/4 로그 기준 정배열 차단이 87건이었으므로 **실제 영향이 있었다.**
→ `BARRO_ZONE_MOM_GATE_SHADOW`(게이트별) 신설로 수정(main `33f52e9`, PR #251).

### ★교정 2 — 당일 미완성 봉 기준 불일치

데몬은 **당일 봉을 포함**해 넘기는데(trend 게이트 규약) 측정은 **진입 전일 종가** 기준이었다.
갭상승일에 당일 봉이 모멘텀을 부풀려 시뮬↔라이브가 어긋난다.
→ `candles[-2]` vs `candles[-22]` 로 직전 봉 기준 산출. 최소 봉수 21 → 22.

### ★교정 3 — 초판의 테스트 수치는 워크트리 한정

초판은 "전체 2,471 passed"를 보고했으나 이는 **워크트리(`data/` 없음)** 기준이다.
메인 체크아웃에서는 **선존재 실패 5건**이 있다(ohlcv_exchange 2 · screener_api 2 ·
theme_snapshots 1). 동일 코드가 워크트리 통과·메인 실패이며 `ea5da7c`(변경 이전)
대조로 **이 변경이 원인이 아님**을 확인했다. 다만 보고 수치가 환경 한정이었다.

현재 검증: 게이트 테스트 15 passed · 워크트리 전체 2,475 passed, 10 skipped ·
메인 체크아웃 선존재 5 failed(별건) · `import app` OK

## 6. 권고 (교정)

1. **실차단 전환 보류.** jackknife 5건 역전은 "표본이 부족하다"는 뜻이다. 초판의
   "SHADOW 1~2주 후 전환" 권고는 **근거가 약했다** — 기간이 아니라 **표본 수**가 기준이어야 한다.
2. **게이트별 shadow 로만 측정한다**(`BARRO_ZONE_MOM_GATE_SHADOW=1`). 전역 SHADOW 는 금지 —
   정배열 차단이 함께 풀린다.
3. **캐시 결손 5건 복구** 후 43건 전수로 재측정한다.
4. **f_zone 은 제외**를 전제로 검토한다. 현재 구현은 존3 전체에 적용되므로, 실차단 전환 시
   전략별 분리(`gold_zone` 한정)를 먼저 결정해야 한다.
5. 선존재 테스트 실패 5건은 **별건으로 해결**한다. 앞으로 회귀는 워크트리와 메인 체크아웃
   **양쪽**에서 돌린다.
