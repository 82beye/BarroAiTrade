## 6. ★미결정 — DCA 유지 여부 (사용자 응답 대기)★

10/26 DCA 완료 포지션 **2건이 모두 손절**됐다(−10.55% · −9.73%). 반사실 비교:

| | 실제(DCA) | A: 전량 단일진입 | B: T1만 보유 |
|---|---|---|---|
| 합계 | **−516,831** | −557,208 | −282,764 |
| 차이 | — | DCA **+40,377 유리** | DCA **−234,067 불리** |

- A(같은 금액을 어차피 전부 투입) 전제면 분할이 평단을 낮춰 유리
- B(T2 미발동) 전제면 **하락 종목에 추가 투입**한 만큼 손실 증폭

**표본 2건 — 통계적 결론 아님(추정).** 다만 6/10 에 gold_zone DCA 를 끈 것과 같은 패턴이다.

제시한 선택지: ①`BARRO_AI_SWING_DCA_ENABLED=0` ②발동선 −3%→−5% ③현행 유지(표본 3~5건까지).
**분할매수는 사용자 직접 지시 사항이므로 임의 변경하지 않는다(§2 S4).**

## 7. 구조적 한계 (관찰)

### 7.1 하드 손절은 갭하락을 막지 못한다
10/26 휴니드 −10.9% · 코세스 −8.5% 는 **09:05:07~09 동시 청산** — 시가가 이미 −8% 아래였다.
SL 을 조여도 동일(갭 빈도만 증가). 코세스는 −3% 를 거치지 않고 −8.5% 로 직행해 **T2 미발동**.

### 7.2 손절 종목은 DCA 대상에서 제외된다 (의도된 설계)
`scripts/intraday_buy_daemon.py:1046` — `sl_symbols` 에 든 종목은 DCA 루프에서 `continue`.
손절선을 뚫은 종목에 추매하면 같은 사이클에 더 큰 수량이 손절되므로 타당.

### 7.3 미검증
- **알멕 −9.9%**(장중, 갭 아님)가 손절선을 1.9%p 초과한 원인 — 5분봉 캐시가 전일분이라 장중 경로 **미검증**
- 데몬 프로세스의 실제 env 값 — macOS 가 노출하지 않아 **간접 체인으로만 확인**(크론 소싱·파일 내용·기동 시각·HEAD)
- 매매 알림 텔레그램 실제 수신 여부 — 사용자 확인 필요

## 8. ★보안 — 미조치★

`localhost:3000` 이 **cloudflared + ngrok 2개 터널로 공개 노출** 중이고,
`/api/*` → `localhost:8000` 프록시라 **백엔드 전체가 무인증으로 외부 접근 가능**하다.
외부 URL 로 `/api/accounts/balance` 호출 시 계좌 잔고·보유종목이 그대로 반환됨을 **실측 확인**했다.
2026-07-01 보안검토에서 보고한 내용이 그대로 남아 있다([[security-review-0701]]).

제시한 선택지: ①터널 Basic Auth ②백엔드 JWT 배선 ③불필요 터널 정리.
**터널을 끄면 코덱스 호스팅 대시보드가 데이터를 못 받으므로 임의 중단하지 않았다.**

> 참고: `*.chatgpt.site` 대시보드는 **이 리포가 아니다**(코덱스 호스팅). 해당 문구 grep 0건.
> 전략 표시가 필요하면 코덱스에 `holdings[].strategy / tranches / targets / effective_stop_loss`
> 필드를 전달하면 된다 — 백엔드 추가 작업 불필요.
