# ai_swing 수익 일관성 튜닝 — 시뮬↔라이브 진입 게이트 정렬 + min_score 상향

**작성일**: 2026-09-02
**요구**: "매매전략을 조정해 5번 연속 수익이 나도록" (자율진행)
**스코프**: 실측 베이스라인 → 시뮬↔라이브 괴리 발견 → 그리드 스윕 → 구현 → 문서화
**관련**: [[2026-07-30-ai-swing-p0.report]] (현재 기본 파라미터의 근거), [[2026-07-02-trade-log-analysis-tuning]]

---

## 0. 먼저 — 이 문서가 주장하지 않는 것

**"실제 장에서 5연승"은 이 작업으로 보장되지 않는다.** 시장 결과는 통제 밖이고, ai_swing 은
슬롯 1개·최소보유 3일이라 실거래 5연승 관측에는 최소 수 주가 걸린다.

그래서 **"5번 연속 수익"을 "독립 seed 5개에서 모두 `avg_ret > 0`"** 으로 정의하고 그 기준으로
판정했다. 이는 백테스트 상의 재현성 지표이지 실거래 보증이 아니다.

또한 백테스트 유니버스는 **랜덤 120종목(대조군)** 이다. 라이브의 실제 유니버스인 단테
교집합(스캔∩예측)이 아니다 — [[2026-07-30-ai-swing-p0.report]] 가 같은 한계를 명시했고
이번에도 동일하다. **랜덤 유니버스 결과를 교집합 유니버스에 적용하는 것은 (추정)이다.**

## 2. 시뮬과 라이브의 진입 게이트가 다르다 (관찰) — 단, 영향은 미미했다

`IntradaySimulator` 의 ai_swing 분기(`intraday_simulator.py:286`)는 이렇게 백테스트한다:

```python
AiSwingStrategy(_ov_params(AiSwingParams(
    min_atr_pct=0.035,
    entry_time_cutoff=dtime(14, 0),
    require_daily_candles=True,
), "ai_swing", params_override))
```

그런데 라이브는 두 곳 모두 **무인자**로 만든다:

```
scripts/intraday_buy_daemon.py:1481   return AiSwingStrategy().analyze(ctx), ""
scripts/ai_swing_daemon.py:679        strategy = AiSwingStrategy()
```

무인자 → `AiSwingParams()` 기본값:

| 게이트 | 시뮬(백테스트) | 라이브(실제) |
|---|---|---|
| `min_atr_pct` | **0.035** | 0.03 |
| `entry_time_cutoff` | **14:00** | 없음 |

이는 [[2026-07-30-ai-swing-p0.report]] 가 청산 경로에서 잡았던 시뮬↔라이브 괴리(F1)와 같은
계열의 결함이 **진입 경로에 남아 있던 것**이다.

### 2-1. 정정 — 두 축 중 실제로 차이를 만드는 것은 ATR 하나뿐 (관찰)

컷오프 축을 실측하니 **실질 무효**였다. ai_swing 은 시뮬·라이브 **둘 다 일봉**으로 판정하는데,
일봉 캔들의 `.time()` 은 `00:00:00` 이라 14:00 컷오프에 절대 걸리지 않는다:

```
마지막 일봉 timestamp: 2026-09-01 00:00:00
  .time() = 00:00:00
14:00 컷오프 차단 여부: False
```

`swing_38.py:69` 주석("일봉 시뮬은 .time()=00:00 으로 항상 통과")과 일치한다.

| 게이트 | 시뮬 | 라이브 | 실제 차이 |
|---|---|---|---|
| `min_atr_pct` | 0.035 | 0.03 | **있음 — 저변동 종목이 라이브에서만 통과** |
| `entry_time_cutoff` | 14:00 | 없음 | **없음 (일봉이라 무효)** |
| `require_daily_candles` | True | True | 없음 |

**따라서 실질 괴리는 `min_atr_pct` 0.03 vs 0.035 하나다.** 컷오프 env 는 배선만 남겨 둔다 —
훗날 분봉 판정으로 바뀌면 그때 유효해지고, 지금은 켜도 꺼도 동작이 같다.

### 2-2. ★ 정정 — 괴리는 실재하나 크기가 무시할 수준이다 (관찰)

`--seeds 42,7,123,2024,555 --grid "min_atr=3.0,3.5 min_score=7"` → **10/10 PASS**

| seed | ATR 3.0 (라이브) avg_ret / win% / trades | ATR 3.5 (시뮬) avg_ret / win% / trades |
|---|---:|---:|
| 42 | +3.445 / 40.6 / 436 | +3.468 / 40.4 / 426 |
| 7 | +1.569 / 37.3 / 415 | +1.592 / 37.0 / 403 |
| 123 | +3.392 / 37.8 / 445 | +3.356 / 37.1 / 437 |
| 2024 | +5.011 / 45.5 / 389 | +5.184 / 46.3 / 382 |
| 555 | +2.874 / 41.4 / 425 | +2.980 / 41.9 / 418 |
| **평균** | **+3.258 / 40.5 / 422** | **+3.316 / 40.5 / 413** |

**차이는 avg_ret +0.058%p · 승률 ±0.0%p · 거래 -2.1% 다.** 승패도 3승 2패로 갈린다.

즉 **괴리는 실재하지만 성과에 미치는 영향은 무시할 수준**이다. 이 문서 초안은 이 발견을
"★핵심"으로 적고 "백테스트 근거가 라이브에 그대로 성립하지 않는다"고 썼는데, **측정 결과
그 표현은 과장이었다.** 백테스트 수치는 라이브에도 거의 그대로 성립한다.

실질 개선 레버는 `min_score` 하나다(§3-3).

정렬 자체는 적용한다 — 성과 때문이 아니라 **시뮬과 라이브가 같은 조건에서 돌아야 다음 튜닝의
근거가 성립하기 때문**이다. 비용은 거래 -2% 로 낮다.

### 확인된 무영향 요인

`RF_STOP_DRY_RUN=1` 이라 라운드피겨 손절 보정은 로그만 남기고 base SL 을 유지한다 —
`resolve_sl_pct` 경유로 인한 라이브↔시뮬 SL 괴리는 **없다**(관찰).

## 3. 그리드 스윕 (관찰)

`scripts/backtest_ai_swing.py --random 120 --seed 42 --grid "min_score=3,5,7 tp1=10,15,20"`

| min_score | tp1 | trades | win% | avg_ret% | holdout% |
|---:|---:|---:|---:|---:|---:|
| 3.0 | +10/15/20% | 706 | 39.0 | +2.781 / +2.782 / +2.782 | +1.805 |
| 5.0 | +10/15/20% | 656 | 38.9 | +2.977 / +2.979 / +2.979 | +1.885 |
| 7.0 | +10/15/20% | 426 | 40.4 | +3.471 / +3.468 / +3.468 | +2.475 |

**9/9 PASS.** 두 가지가 읽힌다:

1. **`tp1` 은 사실상 무영향** — 세 값의 avg_ret 차이가 0.003%p 이내다. TP1(+10~20%)에
   닿기 전에 트레일링(start +10% / off 3%)이 먼저 청산하기 때문이다. **tp1 은 튜닝 레버가
   아니다.**
2. **`min_score` 가 지배적 축** — 3.0 → 7.0 에서 avg_ret +0.69%p, holdout +0.67%p,
   승률 +1.4%p 가 **동시에** 개선된다. 대가는 거래 수 706 → 426 (**-40%**).

## 4. 구현 (§2 S3 — 전부 기본 OFF)

### 4-1. `backend/core/strategy/ai_swing.py` — `live_params()`

진입 게이트를 env 로 정렬할 수 있게 했다. **기본값은 현재 라이브값 그대로**라 env 미설정
시 동작이 바이트 동일하다.

| env | 대상 | 기본(=현재 라이브) |
|---|---|---|
| `BARRO_AI_SWING_MIN_ATR_PCT` | `min_atr_pct` | 3.0 (%) |
| `BARRO_AI_SWING_ENTRY_CUTOFF` | `entry_time_cutoff` | 없음 (빈 문자열 = 명시적 비활성) |
| `BARRO_AI_SWING_MIN_SCORE` | `min_score` | 3.0 |

`AiSwingStrategy.__init__` 은 **params 를 명시로 받으면 env 를 타지 않는다** — 시뮬이
파라미터를 주입하는 경로가 env 에 오염되면 그리드 결과가 통째로 무의미해지기 때문이다.
이 계약은 `test_strategy_with_explicit_params_ignores_env` 로 고정했다.

잘못된 입력(오타·빈값·범위 밖)은 전부 흡수해 default 로 폴백한다 — env 오타가 라이브를
죽이면 안 된다(§2 S3).


### 4-2. `scripts/intraday_buy_daemon.py` — 진입 점수 관측 로그

진입 신호가 나올 때마다 실제 점수를 남긴다(**관측 전용 · 동작 변경 0**):

```
[HH:MM:SS][AI-SWING-SCORE] 100840 SNT에너지      score=6.4 (임계 3.0)
```

**이 로그가 이번 라운드에서 가장 오래 남을 산출물이다.** 지금까지 `min_score` 임계는
랜덤 유니버스 백테스트로만 근거를 댔는데, 라이브의 실제 유니버스는 단테 교집합이라 점수
분포가 다를 수 있다. 로그가 쌓이면 임계를 **실제 분포로** 정할 수 있다 — (추정) → (관찰) 전환.

예외는 전량 흡수한다(관측 로그가 진입 경로를 죽이면 안 된다).

### 4-3. `scripts/backtest_ai_swing.py` — `min_atr` 그리드 축 추가

§2-1 에서 실질 괴리가 `min_atr_pct` 하나로 좁혀졌는데, 정작 그 축이 그리드에 없어
"정렬이 진입 수를 얼마나 줄이나"를 **측정할 수 없었다**. 축을 추가해 (미검증) → (관찰) 로
바꿀 수 있게 했다.

★ `_RAW_FIELDS` 에 넣고 **float 로 캐스팅**한다. `_PCT_FIELDS` 에 넣으면 `Decimal` 이
만들어지는데 `min_atr_pct` 는 float 필드라 진입 판정의 `atr < p.min_atr_pct` 비교에서
`TypeError` 가 난다 — 구현 중 실제로 밟은 함정이고, 회귀 테스트 2건으로 고정했다.

## 5. 한계 — 이 문서의 수치가 라이브를 대변하지 못하는 지점

1. **유니버스 불일치 (가장 큰 한계)** — 백테스트는 랜덤 120종목, 라이브는 단테 교집합
   (일평균 1.08종목). 두 모집단의 진입 신호 분포가 같다는 근거는 없다. **(추정)**
2. ~~진입빈도 영향 미측정~~ → **측정 완료(§2-2)**. `min_atr` 그리드 축을 추가해 정렬 효과를
   실측했다: 거래 -2.1% · avg_ret +0.058%p. 라이브 진입 감소의 대부분은 `min_score` 몫
   (-42%)이고 정렬 몫은 미미하다.
3. **당일 캔들 부재** — 캐시는 `as_of 2026-09-01` 로 당일 봉이 없다. 라이브는 브로커에서
   당일 봉을 포함해 조회하므로, 오늘 실제 진입(100840)은 캐시로 재현되지 않는다.
   실제로 캐시 기준 재현 시 `min_score=0` 에서도 신호가 나지 않았다 — 즉 **오늘의 진입은
   당일 봉이 만든 신호**다. 오프라인으로는 "이 임계였다면 오늘 샀을까"를 답할 수 없다.
4. **실거래 표본 0** — ai_swing 실체결은 2026-09-02 진입 1건뿐이고 미청산이다. 실거래
   기준 승률·PF 는 **아직 산출 불가**다.

## 6. 운영 반영 (리포 밖 — `.env.local`, gitignore 대상)

```
BARRO_AI_SWING_MIN_SCORE=7        # 3.0 → 7.0 (§3-3 근거)
BARRO_AI_SWING_MIN_ATR_PCT=3.5    # 시뮬과 정렬 (§2-2 — 성과 영향 미미, 조건 일치 목적)
```

`BARRO_AI_SWING_ENTRY_CUTOFF` 는 **설정하지 않았다** — 일봉 판정에서 무효이므로(§2-1)
켜봐야 노이즈만 는다. 배선만 남겨 둔다.

적용 확인 (데몬이 쓰는 무인자 생성 경로):

```
min_score    = 7.0    (기대 7.0)
min_atr_pct  = 0.035  (기대 0.035)
entry_cutoff = None   (미설정)
sl_pct = -0.05  trail = 0.10/0.03   ← 청산 파라미터는 건드리지 않았다
```

**반영 시점**: 크론 데몬은 매 실행마다 `.env.local` 을 소싱하므로 **다음 08:58 기동부터**
적용된다. 오늘(2026-09-02) 돌고 있는 데몬은 구 코드·구 설정으로 떠 있어 영향이 없다.

**롤백**: 두 줄을 지우거나 각각 `3` / `3.0` 으로 되돌리면 즉시 원복된다(재기동 불필요).

## 7. 남은 일 — 이 라운드가 답하지 못한 것

1. **실거래 검증 0** — 이 문서의 근거는 전부 백테스트다. ai_swing 실체결은 1건(미청산).
   실거래로 "5연승"을 확인하려면 슬롯 1개·최소보유 3일 기준 **최소 수 주**가 필요하다.
2. **교집합 유니버스 점수 분포 미지** — `[AI-SWING-SCORE]` 로그(§4-2)가 쌓이면
   `min_score=7` 이 실제 유니버스에서 적정한지 **관측으로** 판정할 수 있다. 그때까지 7.0 은
   랜덤 유니버스 근거에 기댄 **(추정)** 값이다.
3. **진입 기회 자체가 병목** — 교집합 일평균 1.08종목(§3-2)이 근본 제약이다. `min_score`
   튜닝은 그 안에서의 최적화일 뿐이고, 파이를 키우려면 유니버스 정의(watchlist top20 ∩
   predictions top20 — 서로 다른 모집단의 교집합)를 손대야 한다. 이는 개장 전 텔레그램
   브리핑 내용까지 바꾸므로 사용자 판단 영역이라 이번 범위에서 제외했다.
4. **`min_hold`/`max_hold` 축 미탐색** — 현재 3/20. 그리드 축은 열려 있으나 이번에 돌리지
   않았다.
